> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **사용자(본인)**,
I want **내 프로필을 조회하고 username을 수정하**,
so that **내 계정 정보를 원하는 대로 관리할 수 있다**.

## Acceptance Criteria

1. `GET /api/users/me`는 로그인된 사용자의 프로필(username, email, profileImage, createdAt)을
   반환한다.
2. `PATCH /api/users/me`는 username을 수정할 수 있고, 성공 시 갱신된 프로필을 반환한다.
3. `/profile` 페이지는 현재 사용자 프로필을 보여주고 username을 수정할 수 있는 폼을 제공한다.
4. 미인증 요청은 401 UNAUTHORIZED로 거부된다.
5. username이 빈 문자열이면 400 INVALID_REQUEST가 반환된다.

## Testing

- **Approach:** API 단위/통합 테스트 + UI 폼 제출 수동 확인.
- **Key scenarios:** 프로필 조회 성공, username 수정 성공, 미인증 401, 빈 username 400.
- **Per-AC verification:** AC#1 → 통합 테스트로 GET 응답 필드 확인; AC#2 → PATCH 후 DB 값 확인;
  AC#3 → 수동으로 폼 제출 후 화면 갱신 확인; AC#4 → 세션 없이 요청 시 401 확인; AC#5 → 빈 문자열
  PATCH 요청 시 400 확인.
- **Fixtures / mocks:** 로그인 세션 mock, 테스트 User 레코드.
- **Edge cases to cover:** 매우 긴 username(100자 초과) 입력 시 400 처리.
