## Story

As a **사용자(본인)**,
I want **학습 노트를 기반으로 블로그 초안이 자동 생성되**,
so that **블로그 글쓰기의 초기 부담 없이 바로 다듬어 발행할 수 있다**.

## Acceptance Criteria

1. `lib/domain/blog/blogdraft-generator.ts`에 Note 데이터를 받아 OpenAI API로 블로그 초안
   (title, content)을 생성하는 함수가 있다.
2. 생성된 초안은 `lib/domain/blog/blogdraft-service.ts`의 함수로 `blog_drafts` 테이블에
   저장되며, Note 1건당 최대 1건만 존재한다(1:1, `noteId` unique 제약).
3. 이 함수는 노트 생성 파이프라인(3.3)에서 노트 저장 직후 호출되도록 설계된다.
4. 블로그 초안 생성이 실패해도 이미 저장된 Note는 영향받지 않는다 — 함수는 실패 시 에러를
   throw하고, 그 처리(격리)는 호출자(3.3)의 책임으로 위임한다.

## Tasks / Subtasks

- [ ] 블로그 초안 생성 프롬프트 작성 — Note 데이터(summary/concepts/architecture 등) 기반 (AC: #1)
- [ ] OpenAI 호출 및 응답 파싱(title/content) (AC: #1)
- [ ] `blogdraft-service.ts` 저장 함수(unique `noteId` 제약) (AC: #2)
- [ ] 실패 시 에러 throw (호출자가 격리 처리하도록) (AC: #4)

## Dev Notes

- FR-017: "블로그 초안 생성 실패 시에도 노트는 정상적으로 유지된다" — 이 원칙에 따라 이 함수는
  자신의 실패를 그냥 throw만 하고, Job 상태를 직접 조작하지 않는다. 실패 격리(try/catch로 감싸
  Job을 FAILED로 만들지 않는 처리)는 3.3의 책임이다. [Source: prd.md#fr-017-블로그-초안-생성--must]
- BlogDraft 스키마(`noteId` unique, `content` 필드가 export의 소스)는 1.2에서 정의된 대로
  사용한다. [Source: architecture.md#5-data-model]
- 저장되는 `content`는 5.3(Markdown export)에서 그대로 파일로 스트리밍될 예정이므로, 순수
  Markdown 텍스트로 생성한다. [Source: architecture.md#adr-008-markdown-export를-db-저장--다운로드-라우트로-처리]
