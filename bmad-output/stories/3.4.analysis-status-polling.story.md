## Story

As a **사용자(본인)**,
I want **분석 Job의 진행 상태를 확인하**,
so that **분석이 언제 끝나는지, 실패했는지 알 수 있다**.

## Acceptance Criteria

1. `GET /api/analysis/{jobId}`는 본인 소유 Job의 상태(PENDING/PROCESSING/COMPLETED/FAILED)를
   반환한다.
2. COMPLETED 상태일 때 `noteId`가 함께 반환된다.
3. FAILED 상태일 때 `errorMessage`가 함께 반환된다.
4. 타인 소유 Job 조회 시 403 FORBIDDEN, 존재하지 않는 `jobId`는 404 NOT_FOUND를 반환한다.
5. `/analysis` 화면에서 진행 중인 Job은 TanStack Query로 일정 간격 폴링되어 상태가 자동
   갱신되고, COMPLETED/FAILED가 되면 폴링이 멈춘다.

## Dev Notes

- 폴링은 TanStack Query `refetchInterval`로 구현한다 (ADR-004 LOCKED — 별도 전역 상태
  라이브러리를 도입하지 않는다). [Source: architecture.md#adr-004-서버-상태-우선--tanstack-query-폴링]
- 소유권 검증은 1.4의 `requireUser()` + 리소스 `userId` 일치 확인 패턴을 재사용한다.
  [Source: architecture.md#nfr-002--security--encryption-at-rest-authentication]
- COMPLETED/FAILED 상태가 되면 클라이언트에서 `refetchInterval`을 해제해 불필요한 폴링을
  멈춘다. [Inference]

- **Edge cases to cover:** 폴링 중 네트워크 오류 시 TanStack Query 기본 재시도 정책에 맡긴다.

**진행 요약:**
- `@tanstack/react-query` 설치. **이 프로젝트에 처음 도입되는 라이브러리라
  `QueryClientProvider`가 트리 상단에 필요**했음 — `components/providers/QueryProvider.tsx`
  (client component)를 새로 만들고 `app/(web)/layout.tsx`(2.1이 소유한 shared/contended
  파일)에 최소한으로 추가해 `{children}`을 감쌌다. Owned File Scope에 명시되진 않았지만
  TanStack Query가 동작하려면 필수적인 인프라라 추가함. [Learning]
- `GET /api/analysis/[jobId]`: `requireUser()` → Job 조회(404) → `job.userId` 일치 확인(403)
  → `{jobId, status, repoUrl, branch, noteId?, errorMessage?}` 반환.
- `hooks/useAnalysisJob.ts`: `refetchInterval`을 콜백 형태(`(query) => query.state.data가
  COMPLETED/FAILED면 false, 아니면 3000ms`)로 구현해 종료 상태에서 자동으로 폴링을 멈춘다.
  이 판단 로직을 `isTerminalStatus()`라는 순수 함수로 분리해서 export — React 렌더링 환경
  (jsdom/testing-library) 없이도 핵심 로직을 단위 테스트할 수 있도록 함. [Learning: 이
  프로젝트는 아직 jsdom/@testing-library/react가 설치돼 있지 않아서, 훅의 상태 전이 판단
  로직만 순수 함수로 뽑아 테스트하는 패턴을 씀]
- `components/analysis/JobStatusBadge.tsx`: 상태별 한글 라벨 표시. 아직 `/analysis` 페이지
  자체는 3.6의 Owned Scope라 이번 스토리에서 만들지 않음 — 훅/배지만 준비.
- 테스트 11건 추가 (route 5건 — 401/404/403/COMPLETED+noteId/FAILED+errorMessage, 훅 로직
  4건). 전체 스위트 84건 통과. `npm run build`/`lint` 통과, curl로 미인증 401 확인.

**후속 스토리를 위한 참고:**
- 3.6이 `/analysis` 페이지를 만들 때 `useAnalysisJob(jobId)` + `JobStatusBadge`를 그대로
  가져다 쓰면 된다.
- 이후 TanStack Query가 필요한 다른 화면들도 이미 세팅된 `QueryProvider`를 재사용하면 되고,
  별도로 다시 wrapping할 필요 없음.
