## Story

As a **사용자(본인)**,
I want **계정을 삭제할 수 있**,
so that **더 이상 서비스를 사용하지 않을 때 내 데이터를 정리할 수 있다**.

## Acceptance Criteria

1. `DELETE /api/users/me`는 로그인된 사용자의 계정과 연관 데이터(AnalysisJob/Note/BlogDraft)를
   삭제한다.
2. 삭제 성공 시 세션이 종료된다.
3. `/profile` 페이지에 "회원 탈퇴" 버튼과 확인(confirm) 단계가 있다.
4. 미인증 요청은 401로 거부된다.

## Dev Agent Record

**완료일:** 2026-08-03 (Ralph loop)
**Branch:** `feature/2.3-account-deletion` (base: `feature/nextjs-migration`)

**진행 요약:**
- `prisma/schema.prisma`는 이미 1.2에서 AnalysisJob/Note/BlogDraft→User 관계에
  `onDelete: Cascade`를 걸어둬서 이번 스토리에서 스키마 변경이 필요 없었다 (Dev Notes가
  "이 스토리에서 보완"이라고 했지만 실제로는 선행 작업에서 이미 완료돼 있었음).
- `lib/domain/user/user-service.ts`에 `deleteAccount(userId)` 추가 — `prisma.user.delete()`만
  호출하면 cascade로 연관 레코드가 전부 삭제됨.
- `DELETE /api/users/me`: `requireUser()` 가드 → `deleteAccount()` → `signOut({redirect:
  false})`로 세션 쿠키 무효화 → `ok({deleted: true})` 반환. `signOut()`을 Route Handler 안에서
  호출할 때는 `redirect: false`가 필수 — 기본값(true)이면 Auth.js가 Next.js의 `redirect()`를
  던져서 우리 JSON 엔벨로프 응답이 아니라 리다이렉트 응답이 나가버린다. [Learning]
- `components/user/DeleteAccountButton.tsx`: 클라이언트 컴포넌트, `window.confirm()`으로 1차
  확인 후 `fetch(DELETE)`, 성공 시 `router.push("/")` + `router.refresh()`.
- 테스트: `user-service.test.ts`에 `deleteAccount` 케이스 추가, `tests/api/users/me.test.ts`에
  DELETE 4케이스 추가(401, cascade 삭제 — AnalysisJob/Note/BlogDraft까지 실제로 만들어서 전부
  삭제됐는지 확인, signOut 호출 여부 확인). 전체 스위트 32건 통과.
- `npm run build`/`lint` 통과, curl로 미인증 401 확인.
- 이번 스토리도 실제 GitHub 자격증명 없이 세션 mock만으로 전체 자동 검증 가능했음.
