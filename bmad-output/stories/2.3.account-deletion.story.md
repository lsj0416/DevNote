## Story

As a **사용자(본인)**,
I want **계정을 삭제할 수 있**,
so that **더 이상 서비스를 사용하지 않을 때 내 데이터를 정리할 수 있다**.

## Acceptance Criteria

1. `DELETE /api/users/me`는 로그인된 사용자의 계정과 연관 데이터(AnalysisJob/Note/BlogDraft)를
   삭제한다.
2. 삭제 성공 시 세션이 종료된다.
3. `/profile` 페이지에 "회원 탈퇴" 버튼과 확인(confirm) 단계가 있다.
4. 미인증 요청은 401로 거부된다.

## Tasks / Subtasks

- [ ] 삭제 성공 시 세션 종료 처리 (AC: #2)
- [ ] `/profile` 페이지에 탈퇴 버튼 + 확인 다이얼로그 UI (AC: #3)

## Dev Notes

- Prisma 관계에 `onDelete: Cascade`를 설정해 User 삭제 시 연관 AnalysisJob/Note/BlogDraft가
  함께 삭제되도록 한다 — `schema.prisma`의 관계 정의를 이 스토리에서 보완한다.
  [Source: architecture.md#5-data-model]
- FR-005는 Could 우선순위 — 최소 구현으로 충분하다. [Source: prd.md#fr-005-회원-탈퇴--could]
- 탈퇴 후에는 2.1에서 구성한 `signOut()`을 호출해 세션을 종료한다.
  [Source: architecture.md#adr-003-github-oauth-via-authjs-jwt-세션]

## Testing

- **Approach:** API 통합 테스트(cascade 삭제 확인) + UI 확인 다이얼로그 수동 확인.
- **Key scenarios:** 탈퇴 시 4개 테이블의 관련 레코드 모두 삭제, 탈퇴 후 세션 무효화, 미인증
  401.
- **Per-AC verification:** AC#1 → 탈퇴 후 DB에서 User 및 연관 AnalysisJob/Note/BlogDraft 존재
  여부 확인; AC#2 → 탈퇴 후 보호 라우트 접근 시 리다이렉트 확인; AC#3 → 수동으로 확인 다이얼로그
  없이 즉시 삭제되지 않는지 확인; AC#4 → 미인증 401 확인.
- **Fixtures / mocks:** 연관 AnalysisJob/Note/BlogDraft가 있는 테스트 User.
- **Edge cases to cover:** 진행 중인(PROCESSING) AnalysisJob이 있는 상태에서 탈퇴 시에도 단순
  cascade 삭제로 처리한다 (별도 방어 로직 불필요). [Inference]
