# 4.3: 노트 삭제

**Story ID:** 4.3
**Epic:** 4 — 학습 노트
**Slug:** note-deletion
**Status:** done
**Branch:** `feature/4.3-note-deletion` (base: `feature/nextjs-migration`)

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **사용자(본인)**,
I want **더 이상 필요 없는 학습 노트를 삭제하**,
so that **노트 목록을 정리할 수 있다**.

## Acceptance Criteria

1. `DELETE /api/notes/{noteId}`는 본인 소유 노트를 삭제하고, 연관된 BlogDraft가 있다면 함께
   삭제된다.
2. 타인 소유 노트 삭제 시도는 403으로 거부된다.
3. `/notes/{noteId}` 상세 페이지에 삭제 버튼과 확인 단계가 있다.
4. 삭제 성공 시 `/notes` 목록으로 리다이렉트된다.

## Tasks / Subtasks

- [x] `note-service.ts`에 `deleteNote`(cascade BlogDraft) 함수 추가 (AC: #1)
- [x] `DELETE /api/notes/{noteId}` Route Handler (AC: #1, #2)
- [x] 상세 페이지에 삭제 버튼 + 확인 다이얼로그 (AC: #3, #4)

## Testing

- **Approach:** API 통합 테스트(cascade 확인) + UI 확인 다이얼로그 수동 확인.
- **Key scenarios:** 정상 삭제 시 Note+BlogDraft 모두 삭제, BlogDraft가 없는 Note 삭제 시에도
  정상 동작, 타인 소유 403.
- **Per-AC verification:** AC#1 → 삭제 후 DB에서 Note/BlogDraft 존재 여부 확인(두 케이스: 있음/
  없음); AC#2 → 타인 소유 삭제 시도 403 확인; AC#3 → 수동으로 확인 다이얼로그 노출 확인; AC#4 →
  삭제 후 리다이렉트 확인.
- **Fixtures / mocks:** BlogDraft가 연결된 테스트 Note, 연결되지 않은 테스트 Note.
- **Edge cases to cover:** BlogDraft가 없는 Note 삭제(정상 동작해야 함).

**진행 요약:**
- `deleteNote(noteId)`는 `prisma.note.delete()`만 호출 — `BlogDraft.note`의
  `onDelete: Cascade`(1.2에서 이미 설정)가 자동으로 연관 BlogDraft를 지워주므로 별도
  트랜잭션/명시적 삭제 로직이 필요 없었다. BlogDraft가 없는 노트도 그냥 동작.
- `DELETE /api/notes/[noteId]`: 4.2의 GET과 동일한 조회→404/403 판별 패턴 재사용 후 삭제.
- `components/note/DeleteNoteButton.tsx`: 2.3의 `DeleteAccountButton` 패턴 재사용
  (`window.confirm()` → DELETE → 성공 시 `router.push("/notes")` + `router.refresh()`).
- 테스트 6건 추가 (note-service 2건 — cascade 있음/없음, API 4건 — 401/404/403(삭제 안 됨
  확인 포함)/성공(cascade 확인)). 전체 스위트 105건 통과. `npm run build`/`lint` 통과,
  curl로 미인증 401 확인.
