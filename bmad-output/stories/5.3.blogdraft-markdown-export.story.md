# 5.3: Markdown export 다운로드

## Story

As a **사용자(본인)**,
I want **블로그 초안을 Markdown 파일로 내려받**,
so that **내가 원하는 플랫폼에 수동으로 발행할 수 있다**.

## Acceptance Criteria

1. `POST /api/notes/{noteId}/blog-draft/export`는 해당 초안의 `content`를 `.md` 파일로
   스트리밍 응답한다 (`Content-Type: text/markdown`, `Content-Disposition: attachment`).
2. 본인 소유가 아니면 403, 초안이 없으면 404를 반환한다.
3. `/notes/{noteId}` 페이지의 블로그 초안 섹션에 "Markdown 다운로드" 버튼이 있다.

## Dev Agent Record

**진행 요약:**
- `lib/domain/blog/slugify.ts`: 한글을 보존하는 slug 생성. **실제 버그를 구현 중 직접
  발견/수정함**: `NFKD` 정규화는 한글 완성형 음절(가-힣)을 개별 자모로 분해하는데, 분해된
  자모는 `가-힣` 허용 범위 밖이라 필터링되어 한글 제목이 전부 "untitled"가 되는 문제가 있었다.
  Latin 발음 구별 기호를 제거한 뒤 `.normalize("NFC")`로 재조합해서 한글은 완성형으로
  복원되고 Latin 억양만 제거되도록 수정. 회귀 테스트로 고정함. [Learning]
- `POST /api/notes/{noteId}/blog-draft/export`: 404/403 판별(5.2와 동일 패턴) 후
  `Response(content, {headers})`로 직접 스트리밍. **두 번째 버그 발견/수정**: 파일명에 한글이
  포함되면 `Content-Disposition` 헤더 값이 ByteString이어야 하는 제약(Latin-1) 때문에
  "Cannot convert argument to a ByteString" 런타임 에러가 났다. RFC 6266의
  `filename*=UTF-8''<percent-encoded>` 확장 형식 + ASCII-only 폴백(`filename="blog-draft.md"`
  또는 원본이 ASCII면 그대로)으로 해결. [Learning]
- `components/blog/ExportButton.tsx`: POST 응답을 blob으로 받아 `URL.createObjectURL` +
  임시 `<a download>` 클릭으로 다운로드 트리거 (POST라 `<a href>` 직접 사용 불가).
  `BlogDraftSection`에 `noteId` prop을 추가해 초안이 있을 때만 버튼 노출.
- 테스트 10건 추가 (slugify 5건 — 한글 보존 회귀 테스트 포함, export route 5건 — 401/404/403/
  헤더+본문 확인/ASCII 파일명 케이스). 전체 스위트 **119건 전부 통과**. `npm run build`/`lint`
  통과, curl로 미인증 401 확인.
