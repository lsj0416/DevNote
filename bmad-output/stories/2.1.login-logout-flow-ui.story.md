# 2.1: 로그인/로그아웃 UI 플로우

## Story

As a **사용자(본인)**,
I want **GitHub 계정으로 로그인하고 로그아웃할 수 있는 UI 플로우를 사용하**,
so that **별도 회원가입 없이 바로 서비스를 이용하고 원할 때 세션을 종료할 수 있다**.

## Acceptance Criteria

1. 비로그인 상태로 `/`(랜딩 페이지) 접근 시 "GitHub로 로그인" 버튼이 표시된다.
2. "GitHub로 로그인" 버튼 클릭 시 Auth.js GitHub OAuth 플로우가 시작되고, 로그인 성공 시
   로그인 후 홈(`/analysis`)으로 리다이렉트된다.
3. 로그인 상태에서는 상단 네비게이션에 로그아웃 버튼이 표시되고, 클릭 시 세션이 종료되고
   랜딩 페이지(`/`)로 리다이렉트된다.
4. 로그인하지 않은 사용자가 보호된 페이지(`/analysis`, `/notes`, `/profile` 등)에 직접
   접근하면 랜딩 페이지로 리다이렉트된다.

## Dev Notes

- Auth.js 클라이언트 함수 `signIn("github")`/`signOut()`을 사용하고, 서버 컴포넌트에서는
  `auth()`로 세션을 조회한다. [Source: architecture.md#adr-003-github-oauth-via-authjs-jwt-세션]
- **LOCKED 결정 확인:** FR-002(재발급)와 FR-003(로그아웃)은 Auth.js 세션 갱신과 `signOut()`으로
  대체 구현하기로 확정되어 있으므로, 이 스토리는 커스텀 `/auth/refresh`, `/auth/logout` API를
  만들지 않는다. [Source: prd.md#fr-003-로그아웃--must]
- 보호 라우트 대상은 `/analysis`, `/notes`, `/profile` 등 로그인 이후 화면 전체이며, Epic 3~5에서
  추가될 페이지도 포함한다. 이 스토리는 게이팅 메커니즘(미들웨어)만 구축하고 개별 페이지 내용은
  각 에픽에서 작성한다. [Inference]
- UI 스타일링은 최소한으로 처리한다 — PRD/architecture에 별도 디자인 시스템 요구사항이 없다.
  [Inference]

## Testing

- **Approach:** 컴포넌트 단위 테스트(버튼 클릭 시 Auth.js 함수 호출 여부) + 수동 E2E(실제 GitHub
  로그인 브라우저 플로우).
- **Key scenarios:** 비로그인 랜딩 페이지 렌더링, 로그인 클릭 → OAuth 리다이렉트, 로그인 후
  목적지 확인, 로그아웃 후 세션 종료 확인, 보호 라우트 미들웨어 리다이렉트.
- **Per-AC verification:** AC#1 → 비로그인 세션 mock 상태에서 렌더 확인; AC#2 → 브라우저 수동
  확인(OAuth 리다이렉트 및 콜백 후 URL); AC#3 → 로그아웃 클릭 후 세션 쿠키 제거 확인; AC#4 →
  미들웨어 단위 테스트(비로그인 요청이 보호 경로 접근 시 리다이렉트 응답).
- **Fixtures / mocks:** Auth.js 세션 mock(로그인/비로그인 상태).
- **Edge cases to cover:** OAuth 콜백 실패(사용자 거부) 시 에러 안내.

**진행 요약:**
- 1.1에서 만든 `app/layout.tsx`/`app/page.tsx`(루트 레벨)를 `app/(web)/layout.tsx`/
  `app/(web)/page.tsx`로 이동 — architecture.md의 `app/(web)/**` 구조를 이제부터 준수. 라우트
  그룹이라 URL(`/`)은 그대로 유지됨. 기본 템플릿 `page.module.css`는 실제 랜딩 페이지로
  교체하면서 더 이상 필요 없어 삭제.
- `LoginButton`/`LogoutButton`은 클라이언트 컴포넌트/`next-auth/react`가 아니라 **Server
  Component + 인라인 Server Action**으로 구현 (`"use server"` 폼 action에서 `lib/auth.ts`의
  `signIn`/`signOut` 직접 호출). Auth.js v5 App Router 공식 권장 패턴이라 별도 `SessionProvider`
  래핑이 필요 없음.
- `app/(web)/layout.tsx`는 서버 컴포넌트로 `auth()`를 호출해 로그인 상태면 상단에
  `LogoutButton`을 렌더링.
- `middleware.ts`: `auth((req) => {...})` 래퍼로 `/analysis`, `/notes`, `/profile` 접근 시
  `req.auth` 없으면 `/`로 307 리다이렉트.
- **중요 이슈 발견 및 수정:** middleware는 기본적으로 Edge Runtime에서 도는데, `lib/auth.ts` →
  `lib/domain/auth/encryption.ts`가 Node `crypto` 모듈을 사용해서 빌드 시
  "Node.js module … not supported in Edge Runtime" 에러가 났다. Auth.js 설정을
  Edge/Node용으로 분리하는 대신, Next.js 16의 Node.js Middleware 기능(`export const config =
  { runtime: "nodejs" }`)으로 middleware 자체를 Node 런타임에서 돌려 해결 — `lib/auth.ts`를
  그대로 재사용할 수 있어 더 간단했다. [Learning]
- 빌드 중 "middleware 파일 컨벤션은 deprecated, proxy 사용 권장" 경고가 뜨는데, 스토리
  Owned File Scope가 명시적으로 `middleware.ts`라서 그대로 유지함 (기능은 정상 동작, 향후
  Next.js 메이저 업그레이드 때 `proxy.ts`로 이름 변경 고려).
- 단위 테스트 2건 추가(LoginButton/LogoutButton이 올바른 텍스트/form을 렌더링하는지
  `renderToStaticMarkup`으로 검증, `@/lib/auth`의 signIn/signOut은 모킹). 전체 스위트 22건 통과.
- `npm run build`/`lint` 통과. 로컬 dev 서버로 확인: `/` 비로그인 시 로그인 버튼 노출(AC#1),
  `/analysis` 비로그인 접근 시 307 → `/` 리다이렉트(AC#4).
- **실제 자격증명 필요 — 확인 대기:** AC#2(로그인 클릭 → OAuth 콜백 → `/analysis` 리다이렉트),
  AC#3(로그아웃 클릭 → 세션 종료 → `/` 리다이렉트)는 실제 브라우저로 GitHub 로그인을 완주해야
  확인 가능해 헤드리스 환경에서는 수동 확인 대기로 남김.

**후속 스토리를 위한 참고:**
- `/analysis`, `/notes`, `/profile` 페이지가 아직 없어 미들웨어의 redirect 대상 자체는 있지만
  실제 페이지는 Epic 3~5에서 만들어진다.
- `app/(web)/layout.tsx`와 `middleware.ts`는 shared/contended — 이후 스토리가 네비게이션 링크나
  보호 경로를 추가할 때 이 파일을 다시 건드리게 된다 (2.1에 Blocked-by로 직렬화).
