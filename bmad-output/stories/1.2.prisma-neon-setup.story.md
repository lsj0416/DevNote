# 1.2: Prisma 스키마 정의 및 Neon 연결

**Story ID:** 1.2
**Epic:** 1 — Foundation & Project Setup
**Slug:** prisma-neon-setup
**Status:** done
**Branch:** `feature/1.2-prisma-neon-setup` (base: `feature/nextjs-migration`)

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **개발자(본인)**,
I want **Prisma 스키마로 도메인 4개 모델(User/AnalysisJob/Note/BlogDraft)을 정의하고 Neon
PostgreSQL에 연결하**,
so that **이후 모든 도메인 기능이 타입 안전한 방식으로 데이터를 저장·조회할 수 있다**.

## Acceptance Criteria

1. `prisma/schema.prisma`에 `User`, `AnalysisJob`, `Note`, `BlogDraft` 모델과 `JobStatus` enum이
   architecture.md의 Data Model 절대로 정의되어 있다.
2. Neon PostgreSQL 프로젝트가 생성되어 있고 `DATABASE_URL` 환경변수로 연결된다.
3. `prisma migrate dev`(또는 `db push`)로 스키마가 Neon DB에 반영되어 4개 테이블이 생성된다.
4. `@prisma/adapter-neon` 기반 Prisma Client가 `lib/db.ts`에서 싱글턴으로 export되어 서버리스
   환경에서 커넥션이 재사용된다.
5. 각 모델의 인덱스(`users.github_id` unique, `analysis_jobs.user_id`/`status`/
   `(repo_url, commit_sha)`, `notes.user_id`/`job_id` unique, `blog_drafts.note_id` unique)가
   정의되어 있다.

## Dev Notes

- 4개 엔티티의 속성/관계/인덱스는 architecture.md Data Model 절을 그대로 따른다:
  - `User`: id(cuid, PK), githubId(unique), username, email?, profileImage?, githubToken?(암호화
    저장 예정, 1.3에서 채움), createdAt/updatedAt
  - `AnalysisJob`: id, userId(FK), repoUrl, repoName, branch, commitSha?, status(enum
    PENDING/PROCESSING/COMPLETED/FAILED), errorMessage?, createdAt/updatedAt
  - `Note`: id, userId(FK), jobId(FK, unique), title, summary, concepts(Json), architecture?,
    learningPoints(Json), rawMarkdown, createdAt/updatedAt
  - `BlogDraft`: id, userId(FK), noteId(FK, unique), title, content, createdAt/updatedAt
  [Source: architecture.md#5-data-model]
- 네이밍: Prisma 필드는 camelCase로 정의하고 `@map("snake_case_column")`으로 DB 컬럼명을
  snake_case로 매핑한다 (ADR-006 LOCKED). [Source: architecture.md#adr-006-네이밍-컨벤션-naming-convention--camelcase-api--snake_case-db-casing]
- Neon + Vercel 서버리스 조합은 HTTP/WebSocket 기반 `@prisma/adapter-neon` 드라이버 어댑터를
  사용한다 (ADR-002 LOCKED). Raw SQL은 예외적 성능 최적화가 필요할 때만 허용된다.
  [Source: architecture.md#adr-002-postgresqlneon--prisma-orm]
- Auth.js(1.3)가 Prisma Adapter를 사용하면 `Account`/`Session` 표준 테이블이 추가로 필요하다.
  이번 스토리에서는 도메인 4개 모델만 정의하고, `Account`/`Session`은 1.3에서 Auth.js가 요구하는
  스키마에 맞춰 추가한다. [Inference]
- `(repo_url, commit_sha)` 복합 인덱스는 FR-012(캐시 재사용)/ADR-009(수집 범위 제한 및 캐싱)의
  기반이 된다. [Source: architecture.md#adr-009-github-커밋pr-수집-범위-제한-및-캐싱]

## Testing

- **Approach:** 마이그레이션 적용 후 Prisma Studio 또는 간단한 seed 스크립트로 각 모델의 CRUD가
  가능한지 수동 확인.
- **Key scenarios:** 마이그레이션 성공, 4개 테이블 생성 확인, FK 제약 동작 확인, unique 제약
  동작 확인.
- **Per-AC verification:** AC#1 → schema.prisma 코드 리뷰; AC#2 → `prisma db pull` 또는 Studio
  접속으로 연결 확인; AC#3 → 마이그레이션 로그 + Neon 콘솔에서 테이블 존재 확인; AC#4 → 로컬에서
  Prisma Client import 후 간단한 쿼리(예: `findMany`) 실행 확인; AC#5 → Neon 콘솔 또는 `\d
  <table>`로 인덱스 확인.
- **Fixtures / mocks:** 테스트용 더미 `User` 1건 seed 스크립트.
- **Edge cases to cover:** 마이그레이션 실패 시 롤백 절차, `users.github_id` unique 제약 위반
  케이스, `notes.job_id`/`blog_drafts.note_id` unique 제약 위반 케이스.

**진행 요약:**
- Prisma 7.9.1 설치. Prisma 7부터 `datasource` 블록의 `url`/`directUrl`이 schema.prisma에서
  지원되지 않아, 루트에 `prisma.config.ts`를 새로 만들어 `datasource.url`을
  `DATABASE_URL_UNPOOLED`(direct, non-pooled)로 설정 — 마이그레이션은 direct 커넥션을,
  런타임 쿼리는 `lib/db.ts`에서 pooled `DATABASE_URL`을 사용하도록 분리했다. [Learning:
  이후 스토리에서 prisma 관련 CLI 명령(`migrate`, `generate` 등) 실행 시 `.env`를 먼저
  `source`해야 `prisma.config.ts`의 `env()`가 값을 찾는다 — Prisma CLI가 .env를 자동 로드하지
  않음]
- `prisma/schema.prisma`에 User/AnalysisJob/Note/BlogDraft 4개 모델 + JobStatus enum을
  architecture.md Data Model 그대로 정의. camelCase 필드 + `@map`/`@@map`으로 snake_case
  컬럼/테이블명 매핑 (ADR-006).
- Neon은 Vercel Storage 통합(Marketplace)으로 생성 (사용자가 대시보드에서 직접 진행).
  `DATABASE_URL`(pooled), `DATABASE_URL_UNPOOLED`(direct) 둘 다 로컬 `.env`에 확보됨.
- `@prisma/adapter-neon` + `@neondatabase/serverless` + `ws` 설치, `lib/db.ts`에 싱글턴
  패턴으로 PrismaClient(adapter) export (Next.js dev 핫리로드 시 커넥션 중복 생성 방지).
- `npx prisma migrate dev --name init`으로 Neon에 4개 테이블 + 요구된 모든 인덱스
  (`users.github_id` unique, `analysis_jobs.user_id`/`status`/`(repo_url, commit_sha)`,
  `notes.user_id`/`job_id` unique, `blog_drafts.note_id` unique) 생성 확인 (`psql`로 직접 확인).
- 별도 스모크 테스트 스크립트로 create/find/delete + unique 제약 위반 케이스까지 실제 Neon
  DB에 대해 CRUD 동작 확인 (테스트 후 정리 완료, 잔여 데이터 없음).
- `npm run build` 통과 확인 (lib/db.ts 포함 타입체크 정상).

**후속 스토리(1.3)를 위한 참고:**
- 1.3에서 Auth.js Prisma Adapter 도입 시 `Account`/`Session` 모델을 `prisma/schema.prisma`에
  추가해야 한다 (이번 스토리에서 의도적으로 비워둠).
- Prisma CLI 명령 실행 전엔 항상 `set -a; source .env; set +a`로 환경변수를 먼저 로드할 것.
