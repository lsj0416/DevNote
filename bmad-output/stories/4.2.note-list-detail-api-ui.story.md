# 4.2: 노트 목록/상세 조회 API + 화면

**Story ID:** 4.2
**Epic:** 4 — 학습 노트

**Status:** done
**Branch:** `feature/4.2-note-list-detail-api-ui` (base: `feature/nextjs-migration`)

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **사용자(본인)**,
I want **생성된 학습 노트의 목록과 상세 내용을 조회하**,
so that **과거에 학습한 내용을 다시 찾아보고 복습할 수 있다**.

## Acceptance Criteria

1. `GET /api/notes`는 본인 소유 노트 목록(title, summary, createdAt)을 페이지네이션하여
   반환한다.
2. `GET /api/notes/{noteId}`는 노트 상세(summary, concepts, architecture, learningPoints,
   rawMarkdown)를 반환한다.
3. 타인 소유 노트 상세 조회 시 403, 존재하지 않는 노트는 404가 반환된다.
4. `/notes` 목록 페이지와 `/notes/{noteId}` 상세 페이지가 각각 존재한다.

**진행 요약:**
- `lib/domain/note/note-service.ts`에 `listNotes(userId, page, size)`(3.5/4.2 공통 페이지네이션
  형식 `{content, totalElements, totalPages, currentPage}`), `getNoteById(noteId)` 추가.
- `GET /api/notes`, `GET /api/notes/[noteId]` — 상세는 3.4/4.2 패턴대로 먼저 조회 후
  404(없음)/403(타인 소유) 구분.
- `/notes`, `/notes/[noteId]` 페이지는 API를 거치지 않고 Server Component에서
  `listNotes`/`getNoteById`를 직접 호출 (3.5/2.2와 동일 패턴 유지). 상세 페이지는 소유자가
  아니거나 없는 노트일 때 403/404를 구분하지 않고 `notFound()`로 통일 — 페이지 레벨에서는
  다른 사용자에게 "존재는 하지만 접근 불가"임을 노출하지 않는 게 더 안전하다고 판단.
  API는 명세대로 403/404를 구분해서 반환한다. [Learning]
- 테스트 7건 추가 (list 3건, detail 4건 — 401/404/403/200 전부). 전체 스위트 99건 통과.
  `npm run build`/`lint` 통과, curl로 미인증 401/307 확인.

**후속 스토리를 위한 참고:**
- 4.3(노트 삭제)이 `app/api/notes/[noteId]/route.ts`에 DELETE를 추가하고,
  `lib/domain/note/note-service.ts`에 삭제 함수를 이어서 추가한다.
- 5.2(블로그 초안 조회)가 `/notes/{noteId}` 페이지에 블로그 초안 링크/섹션을 추가할 수 있다.
