# 1.1: Next.js 프로젝트 초기화 및 Vercel 배포 연결

**Story ID:** 1.1
**Epic:** 1 — Foundation & Project Setup
**Slug:** nextjs-project-init
**Status:** ready-for-dev
**Branch:** `feature/1.1-nextjs-project-init` (base: `develop`)

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **개발자(본인)**,
I want **Next.js(App Router) 프로젝트를 초기화하고 Vercel에 배포 파이프라인을 연결하**,
so that **이후 모든 기능 개발을 이 위에서 진행하고, 매 변경사항을 즉시 배포·확인할 수 있다**.

## Acceptance Criteria

1. `create-next-app`으로 App Router 기반 TypeScript 프로젝트가 생성되어 있고, 로컬에서 `next dev`로 정상 구동된다.
2. 프로젝트가 Git 저장소에 커밋되어 있고 Vercel 프로젝트와 연결되어 있다.
3. main 브랜치 push 시 Vercel Production 배포가 자동으로 트리거된다.
4. 배포된 프로덕션 URL의 루트 페이지가 200 응답으로 접근 가능하다.
5. 프로젝트에 필요한 환경변수 자리표시자가 `.env.example`에 정의되어 있다 (`DATABASE_URL`,
   `AUTH_SECRET`, `AUTH_GITHUB_ID`, `AUTH_GITHUB_SECRET`, `OPENAI_API_KEY`).

## Dev Notes

- 아키텍처는 Next.js 단일 풀스택(프런트+백엔드 통합)으로 확정되어 있다 — 별도 백엔드 프로젝트를
  만들지 않는다. [Source: architecture.md#adr-001-nextjs-단일-풀스택-애플리케이션]
- 컴포넌트 구조는 `app/(web)/**`(UI), `app/api/**`(Route Handler), `lib/domain/**`(도메인 로직),
  `lib/db`, `lib/auth.ts`로 나뉜다. 이번 스토리는 골격만 만들고 세부 폴더는 이후 스토리에서
  채운다. [Source: architecture.md#4-component-design]
- 비동기 분석 Job 처리를 위해 이후(Epic 3) Vercel Fluid Compute를 활성화해야 하므로, Vercel
  프로젝트 설정에서 Fluid Compute 옵션이 존재하는지 미리 확인해두면 좋다. [Source: architecture.md#adr-007-vercel-fluid-compute-기반-비동기-job-처리]
- 배포 전략은 Vercel Git 연동 자동 배포(main → Production, PR → Preview)이다. [Source: architecture.md#10-deployment-architecture]
- 환경변수 5종(DATABASE_URL/AUTH_SECRET/AUTH_GITHUB_ID/AUTH_GITHUB_SECRET/OPENAI_API_KEY)은
  각각 1.2(Prisma/Neon), 1.3(Auth.js), 4.1·5.1(OpenAI)에서 사용될 예정이므로 이번 스토리에서는
  값 없이 키 이름만 `.env.example`에 정의한다. [Inference]

## Testing

- **Approach:** 수동 검증. 이 스토리는 인프라 셋업이라 단위/통합 테스트 대상 로직이 없다.
- **Key scenarios:** 로컬 dev 서버 기동, Vercel 배포 성공, 루트 페이지 200 응답.
- **Per-AC verification:** AC#1 → `npm run dev` 로컬 구동 확인; AC#2 → Vercel 대시보드에서 프로젝트-리포지토리 연결 확인; AC#3 → git push 후 Vercel 배포 로그에서 자동 트리거 확인; AC#4 → 배포 URL에 `curl -I`로 200 확인; AC#5 → `.env.example` 파일에 5개 키 존재 확인.
- **Fixtures / mocks:** 없음.
- **Edge cases to cover:** 빌드 실패 시 Vercel 배포 로그 확인 절차(문서화 수준으로 충분).
